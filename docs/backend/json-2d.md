# Обмен JSON для решателя 2D

## Назначение

Проект `RadarPlacement.Serialization` — отдельная библиотека на .NET 10.
Она ссылается только на наше ядро `RadarPlacement.Core` и стандартную библиотеку .NET.
Код ядра не изменён, зависимости от генератора сцен и Avalonia не добавлены.
Пользовательского консольного приложения на этом этапе нет.

Публичные классы:

| Класс | Назначение |
| --- | --- |
| `SceneJsonReader2D` | Загрузка исходной сцены и проверка поддерживаемой геометрии |
| `SceneDocument2D` | Модель ядра вместе с исходным JSON, sceneId и идентификатором КИИ |
| `SolverSettingsJson` | Чтение, проверка и сохранение настроек решателя |
| `SolverSettings2D` | Параметры радаров и дискретизации для вызова ядра |
| `ResultJsonWriter2D` | Сохранение сцены с установленными радарами и показателями |
| `ResultJsonOptions` | Включение карт покрытия и форматирование результата |
| `JsonReadLimits` | Ограничения размера и вложенности входного документа |
| `RadarJsonException` | Ошибка данных с путём к проблемному полю |

Все публичные типы и методы снабжены русскими XML-комментариями.

## Минимальный полный цикл из C#

Вызывающий проект подключает `RadarPlacement.Serialization.csproj` через `ProjectReference`.
Пути к файлам выбирает вызывающее приложение. Следующий пример показывает использование
библиотек; это не реализация консольного интерфейса:

```csharp
using RadarPlacement.Core;
using RadarPlacement.Serialization;

var source = await new SceneJsonReader2D().LoadAsync("scene.json");
var settings = await new SolverSettingsJson().LoadAsync("solver-settings.json");

var result = new RadarPlacementSolver2D().Solve(
    source.Scene,
    settings.Radars,
    settings.Discretization);

await new ResultJsonWriter2D().SaveAsync(
    source,
    result,
    "Result/scene.solved.json",
    new ResultJsonOptions { IncludeCoverageGrid = true });
```

`Solve` — синхронный вычислительный метод. Если вызывается из оконного приложения,
расчёт следует запускать в фоновой задаче, как описано в README ядра.
JSON-библиотека также предоставляет синхронные `Load`/`Save` и работу со строками
через `Parse`/`Serialize`. Чтение/сохранение файлов не запускает оптимизацию автоматически.

Результат нужно экспортировать с тем же `SceneDocument2D`, чьё свойство `Scene`
передавалось в `Solve`. Связь проверяется по экземпляру модели. Это защищает от записи
результата одной сцены с чужими идентификаторами или метаданными.

## Входная сцена первой команды

Поддерживается формат `schemaVersion: "1.0"` и `mode: "2D"`.
Контрольный [generated-2d.json](../../tests/RadarPlacement.Serialization.Checks/Fixtures/generated-2d.json)
создан настоящим экспортёром первой команды. Его [происхождение](../../tests/RadarPlacement.Serialization.Checks/Fixtures/README.md)
зафиксировано вместе с версией исходников. Для повторных проверок сеть и исходники
генератора не нужны.

Загрузчик проверяет:

- `sceneId` и идентификаторы объектов — непустые строки; идентификаторы объектов уникальны;
- `coordinateSystem`: `localCartesian`, `meters`, оси `east`, `north`, `up`;
- `bounds.min` и `bounds.max`: конечные X/Y, положительные размеры и Z = 0;
- `terrain.type`: `flat`, `terrain.elevation`: 0;
- `objects`: первым записан единственный `kii`, остальные имеют тип `obstacle`;
- геометрия: `polygonPrism`, четыре разные вершины `footprint.outer`, пустой `holes`,
  `baseElevation = 0` и `height = 0`;
- вершины последовательно обходят прямоугольник со сторонами вдоль осей. Можно начинать
  с любого угла и обходить в любом направлении. Первую вершину в конце не повторяют;
- объекты находятся в сцене, их внутренности не пересекаются. Касания границ допустимы;
- одна зона `radarPlacementZones`, ссылающаяся на КИИ, с поверхностью `roof` и двумя
  разрешениями `outerBoundary`, `center` в любом порядке;
- `observationArea`: `terrainSurface`, `sceneBounds`, `excludeObjectFootprints: true`.

`source.type` принимает известные генератору `generated`, `manual`, `openstreetmap`.
Источник не расширяет возможности геометрии: любой такой документ всё равно должен
содержать один КИИ и прямоугольники без дворов. Поля seed, sequenceIndex и дополнительные
метаданные сохраняются, но не участвуют в расчёте. Диапазоны размеров случайного генератора
здесь не навязываются: геометрически корректная небольшая учебная сцена тоже допустима.

Неверная или пока неподдерживаемая геометрия отклоняется. Загрузчик не заменяет
произвольный контур его ограничивающим прямоугольником, не отбрасывает дворы и не
превращает 3D в 2D. Версия 1.1 с несколькими КИИ пока не поддерживается.
Отсутствующая верхняя граница в будущей 3D-модели будет обрабатываться отдельно;
текущий контракт 2D содержит Z = 0 у обеих границ.

Неизвестные дополнительные поля сцены принимаются и сохраняются в `OriginalJson`.
Поля `radars` и `solver` зарезервированы нашим расширением: исходный загрузчик отклоняет
документ, где они уже присутствуют. Импорт готовых результатов как результатов расчёта
в эту версию библиотеки не входит; файл результата является самостоятельным JSON
для внешнего чтения и визуализации, а не новым входом `SceneJsonReader2D`.

## Настройки решателя

Минимальный документ:

```json
{
  "schemaVersion": "1.0",
  "mode": "2D",
  "radarCount": 2,
  "radius": 3000
}
```

Все четыре поля обязательны. `radarCount` — целое число от 1 до 10.
`radius` — конечное число от 3000 до 7000 метров включительно.
Строки вида `"3000"` вместо чисел не принимаются.

Необязательный объект `discretization` может содержать:

| Поле | По умолчанию | Требование |
| --- | --- | --- |
| `candidateStep` | 100 | Положительное конечное число, метры |
| `coverageStep` | 100 | Положительное конечное число, метры |
| `maxCandidatePositions` | 10000 | Положительный Int32 |
| `maxGridCells` | 1000000 | Положительный Int32 |
| `maxBitsetBytes` | 268435456 | Положительный Int64, байты |

Пропуск объекта или отдельных полей означает применение соответствующих значений
по умолчанию. `null` не означает пропуск и вызывает ошибку. Имена чувствительны к регистру.
Неизвестное поле настроек вызывает ошибку: например, `coverageStepp` не должно
незаметно заменяться стандартным шагом.

`SolverSettingsJson.Validate` выполняет те же проверки для настроек, созданных из UI.
При сохранении записываются все поля, включая фактические значения по умолчанию.
Готовый [пример настроек](../../examples/solver-settings-2d.json) использует более грубую
сетку для быстрого демонстрационного расчёта контрольной сцены.

## Формат результата

В корне остаются все свойства входной сцены: идентификаторы, исходная геометрия,
правила размещения, источник и дополнительные метаданные. Сохранение семантическое:
отступы и экранирование строк могут измениться, побайтовое совпадение не обещается.

Добавляются два поля:

1. `radars` — массив длиной ровно `radarCount`.
2. `solver` — версия расширения, фактические настройки, модель расчёта и показатели.

Одна запись радара:

```json
{
  "id": "radar-001",
  "objectId": "kii-001",
  "position": { "x": 4500, "y": 4500, "z": 0 },
  "radius": 3000
}
```

Здесь координаты приведены для иллюстрации структуры. Фактическое расположение выбирает
ядро. `objectId` ссылается на исходный КИИ. Идентификаторы радаров не пересекаются
с идентификаторами зданий. Совпадающие позиции, когда кандидатов меньше радаров,
получают разные идентификаторы. Вышки и стоимость в режиме 2D не добавляются.

Свойства `solver`:

- `schemaVersion: "1.0"` — версия нашего расширения; исходная версия сцены не меняется;
- `algorithm: "branchAndBound"`, `objective: "coveredArea2D"`,
  `coverageModel: "uniformCellCenters"`;
- `globallyOptimalForDiscreteModel: true` — относится только к выбранной конечной модели;
- флаги прозрачности КИИ, непрозрачности помех, обработки касаний и допустимости
  совместного размещения;
- `settings` — полный документ настроек, который можно прочитать `SolverSettingsJson`;
- `search` — число кандидатов, посещённых и отсечённых узлов;
- `coverage` — геометрия сетки, наблюдаемое/покрытое число ячеек, площади и процент;
- необязательный `coverageGrid` — карты для повторной визуализации без поиска.

Площади измеряются в квадратных метрах и являются оценками по центрам ячеек.
При отсутствии наблюдаемых центров `coveragePercent` равен JSON `null`.
Готовый [пример результата](../../examples/solved-scene-2d.json) рассчитан по контрольному
файлу генератора и примеру настроек. По умолчанию карты не включены.

## Необязательные карты покрытия

Для включения карт передайте `new ResultJsonOptions { IncludeCoverageGrid = true }`.
Они находятся в `solver.coverageGrid`:

```text
encoding:       base64-lsb0
indexOrder:     row-major
rowDirection:   south-to-north
excludedMask:   Base64-строка
coveredMask:    Base64-строка
radarMasks:     [{ radarId, coveredMask }, ...]
```

Количество строк и столбцов берётся из `solver.coverage`. Номер ячейки:
`index = row × columns + column`, нумерация с нуля. Столбцы идут с запада на восток,
строки — с юга на север. В байте младший бит соответствует меньшему индексу:

```csharp
byte[] bytes = Convert.FromBase64String(encodedMask);
bool isSet = (bytes[index / 8] & (1 << (index % 8))) != 0;
```

Длина каждой декодированной маски — `ceil(columns × rows / 8)` байт; лишние биты
последнего байта нулевые. Единица в excludedMask исключает ячейку из наблюдаемой
территории. Единица в общей coveredMask означает покрытие хотя бы одним радаром.
В radarMasks те же биты относятся к одному радару, связанному через radarId.
Исключённые ячейки всегда имеют нулевые биты покрытия.

Маски описывают дискретную сетку, а не точные векторные границы кругов и теней.
Base64 выбран для компактности; настройки и позиции остаются обычными читаемыми числами.

## Ошибки, кодировка и сохранение

Файлы читаются как строгий UTF-8, с BOM или без него. Запись всегда выполняется
в UTF-8 без BOM. Комментарии, завершающие запятые, повторные имена свойств, NaN и Infinity
не допускаются. Десятичный разделитель — точка независимо от культуры Windows.

По умолчанию размер входного файла ограничен 16 МиБ, глубина — 64 уровня. Настройки
`JsonReadLimits` можно передать в `Parse`, `Load` и `LoadAsync`. Максимальная
настраиваемая глубина — 256. Превышения и ошибки данных дают `RadarJsonException`.
Свойство `JsonPath` содержит путь, а Message — пояснение, например:

```text
$.objects[0].geometry.height: В режиме 2D отметки и высоты должны быть равны нулю.
$.radius: Радиус должен быть от 3000 до 7000 метров включительно.
```

Ошибки доступа и отсутствия файла сохраняют стандартные типы .NET, например
`FileNotFoundException`, `IOException`, `UnauthorizedAccessException`.
Проверка размера JSON не заменяет лимиты ресурсов ядра при последующем расчёте.

Существующий файл по умолчанию не перезаписывается. Явная замена требует аргумента
`overwrite: true`. Вызывающий UI сам решает, когда запрашивать подтверждение пользователя.
Новое содержимое записывается во временный файл в целевой папке, затем переносится
на окончательное имя. При ошибке или отмене незавершённый временный файл удаляется.
Отмена после завершённого переноса не откатывает уже успешно сохранённый файл.

Async-методы чтения и записи принимают `CancellationToken`; экспорт карт также проверяет
его при обходе ячеек. Сам синтаксический разбор ограниченного JSON выполняется синхронно;
отмена загрузки проверяется до/после него и во время чтения файла.

## Проверки

```powershell
dotnet build RadarPlacement.Core.slnx --configuration Release --disable-build-servers -m:1
dotnet run --project tests/RadarPlacement.Serialization.Checks --configuration Release --no-build
dotnet run --project tests/RadarPlacement.Core.Checks --configuration Release --no-build
```

25 сценариев JSON проверяют настоящий экспорт генератора, неподдерживаемые сцены,
пересечения, обход контуров, строгие настройки, дубликаты свойств, сохранность метаданных,
все биты карт покрытия, файловые ошибки, перезапись и отмену. Дополнительно проходят
20 прежних сценариев ядра. Временные тестовые файлы создаются внутри bin и очищаются;
исходная контрольная сцена не меняется.
