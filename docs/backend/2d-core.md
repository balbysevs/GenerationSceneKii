# Как устроено ядро 2D

## 1. Что получает и возвращает ядро

Вход — объект `Scene2D`, настройки радаров и настройки дискретизации.
Чтение JSON должно выполняться отдельным адаптером, который создаст эти объекты.
Ядро не должно ссылаться на проекты генератора, даже если формат входных файлов совпадает
с их моделями. Таким образом, обмен между командами остаётся исключительно файловым.

Выход — `RadarPlacementResult2D`. Он содержит исходные параметры, выбранные позиции,
покрытие по каждому радару, объединённую карту и показатели поиска. Сериализация результата
также остаётся задачей отдельного слоя. Консоль и Avalonia смогут вызывать один метод `Solve`.

## 2. Две независимые дискретизации

### Позиции

Пусть ширина КИИ равна W, высота на плане — H, шаг позиций — d.
Число отрезков на горизонтальной стороне `nx = ceil(W / d)`, на вертикальной —
`ny = ceil(H / d)`. Каждая сторона разбивается равномерно; фактический промежуток
может быть меньше d, но не больше. Углы принадлежат соседним сторонам и записываются
только один раз. В конце добавляется центр. Всего кандидатов:

```text
M = 2 × (nx + ny) + 1
```

У прямоугольника 1000 × 1000 м при d = 500 м получается 9 кандидатов:
четыре угла, четыре середины сторон и центр.

### Покрытие

Пусть сцена имеет размеры L × B, а шаг покрытия равен s:

```text
columns = ceil(L / s)
rows    = ceil(B / s)
dx      = L / columns
dy      = B / rows
cellArea = L × B / (columns × rows)
```

Все ячейки имеют одинаковую площадь. Последняя строка и последний столбец не являются
узкими остатками: небольшой перерасчёт размера одинаково применяется ко всей сетке.

Центр ячейки `(column, row)`:

```text
x = minX + L × (column + 0.5) / columns
y = minY + B × (row + 0.5) / rows
```

Если центр принадлежит основанию КИИ или помехи, включая границу, ячейка исключается.
Остальные центры образуют конечное множество наблюдаемых точек U.
В модели вся площадь ячейки представлена её центром: это определение приближения,
а не утверждение, что каждый метр этой ячейки обладает такой же видимостью.

Поэтому маленькая помеха может не уменьшить число наблюдаемых ячеек, но всё равно
перекрывать луч к центру другой ячейки. Для перекрытий используется исходный прямоугольник,
а не его изображение на сетке.

## 3. Геометрическая видимость

Контрольная точка видна кандидату, если одновременно выполнены условия:

1. Точка находится на свободной территории внутри сцены.
2. Евклидово расстояние до кандидата не превышает общий радиус R.
3. Отрезок от кандидата к точке не пересекает ни одну помеху.

КИИ не проверяется в третьем условии: по принятой модели он прозрачен для лучей.
На физическое самозатенение здания эта упрощённая модель не претендует.

В `Visibility2D` пересечение отрезка с прямоугольником проверяется параметрическим
отсечением. Отрезок `P(t) = start + t × (end - start)`, где `0 <= t <= 1`, должен
попасть одновременно в допустимые интервалы по X и Y. Если пересечение интервалов
непусто и содержит точку с `t > 0`, помеха перекрывает луч. Отдельно обработан нулевой
компонент направления, чтобы не делить на ноль у горизонтальных и вертикальных лучей.

Геометрия использует `double`. Нефинитные числа и некоторые случаи, когда double уже
не различает соседние точки заданной сетки, отклоняются. Результат точен для вычисленной
дискретной модели с этими численными правилами; произвольная математическая точность
геометрических вычислений не заявляется.

## 4. Битовые маски покрытия

Одной ячейке соответствует один бит. `ulong` хранит 64 бита, поэтому целая карта
представляется массивом `ulong[]`. Для каждой позиции строится собственная маска.
Внутренний номер ячейки: `row × columns + column`. Исключённые ячейки имеют нулевой бит
во всех масках. Неиспользованные биты в последнем слове также остаются нулевыми.

Объединить покрытия можно побитовым ИЛИ (`|`), а посчитать количество покрытых ячеек —
через `BitOperations.PopCount`. Новые ячейки кандидата C относительно уже покрытых S:

```text
newCells = C & ~S
```

Такая операция сразу исключает двойной учёт перекрытий. Целевая функция имеет целочисленное
значение, поэтому оптимизатору не нужно сравнивать близкие значения площади типа double:

```text
maximize count(union(coverage(candidate) for candidate in selected))
```

После поиска число ячеек умножается на `cellArea`. Для процента знаменатель — число
наблюдаемых ячеек, а не общее число ячеек сцены. При нулевом знаменателе процент не определён.

## 5. Почему поиск глобальный

На первом шаге жадный алгоритм последовательно добавляет радар с наибольшим приростом
покрытия. Это допустимое решение и нижняя оценка максимума. Оно может быть неоптимальным.

Затем метод ветвей и границ перечисляет сочетания кандидатов. Установки одинаковы,
поэтому перестановка тех же позиций не меняет покрытие: достаточно сочетаний, без перебора
перестановок. В рекурсии индексы кандидатов строго возрастают.

Для каждого незавершённого выбора с покрытием S и k свободными радарами вычисляются
две верхние оценки:

1. **Объединение всех оставшихся кандидатов.** Покрытие любого допустимого продолжения
   является подмножеством `S ∪ allRemaining`. Это ограничение верно даже без учёта k.
2. **Сумма k наибольших добавок.** У каждого оставшегося кандидата считается количество
   ячеек вне S. Выбираются k наибольших таких чисел. Их сумма плюс `|S|` не меньше
   покрытия любого продолжения: взаимные перекрытия новых кандидатов в сумме могут
   учитываться несколько раз и только завышают оценку.

Если хотя бы одна верхняя оценка не превосходит лучшего уже найденного результата,
в этой ветви не может находиться лучшее решение. Её можно полностью исключить.
Ветви с возможным улучшением продолжают проверяться. После исчерпания таких ветвей
лучшее найденное решение является глобальным максимумом конечной задачи.

Если покрыты все точки U, максимум уже доказан: больше `|U|` покрыть невозможно.
Именно поэтому иногда точный результат получается без рекурсивного перебора.

При равном значении цели хранится первый найденный вариант в стабильном порядке.
Дополнительных критериев оптимизации, например максимального расстояния между радарами,
в этой версии нет.

### Почему можно выбирать только разные позиции

Повторная установка в уже выбранной позиции не добавляет точек к объединению. Если
кандидатов не меньше числа радаров, любой повтор можно заменить неиспользованной позицией:
покрытие при этом не уменьшится. Значит, существует оптимальное решение с разными позициями.
Когда радаров больше, чем кандидатов, оптимально использовать все кандидаты и добавить
нужное число повторов. Поэтому поиск выбирает `min(K, M)` разных позиций, а результат
всегда содержит ровно K установок.

## 6. Цена точности и отмена

Пусть G — число всех ячеек, M — число кандидатов, O — число помех, K — число радаров.
Построение видимости в худшем случае требует порядка `M × G × O` геометрических проверок.
Некоторые проверки завершаются раньше: например, при превышении радиуса.
Число вариантов размещения в худшем случае равно `C(M, min(K, M))`.
Отсечения могут сильно сократить перебор, но гарантии быстрого расчёта для любой сцены нет.

Матрица масок занимает приблизительно `M × ceil(G / 64) × 8` байт. Суффиксные объединения
для верхних оценок требуют ещё примерно столько же. До их создания проверяется лимит
суммарных битовых буферов. Это проверка ресурсов, а не эвристическое упрощение задачи.

`CancellationToken` проверяется во время построения сетки, масок и поиска. При отмене
выбрасывается `OperationCanceledException`. Промежуточное лучшее покрытие в прогрессе
можно показывать как нижнюю оценку, но успешный результат с признаком оптимальности
возвращается только после доказанного завершения.

Уменьшать два шага удобно независимо: сначала изучать влияние более плотных позиций
при фиксированной сетке оценки, затем уточнять саму оценку площади. Это сравнение моделей,
а не встроенная автоматическая гарантия погрешности непрерывной задачи.

## 7. Границы ответственности

`Geometry`, `Models`, `Configuration`, `Discretization`, `Optimization`, `Results`
находятся внутри одного независимого проекта библиотеки. Они не требуют установленных
приложений первой команды или Димы. Входные коллекции копируются, наружу выдаются
неизменяемые представления; вычислительное состояние создаётся заново на каждый вызов.

Следующие отдельные части проекта смогут использовать библиотеку:

- адаптер JSON преобразует файлы генератора в `Scene2D` и сохраняет результаты;
- консоль разбирает аргументы и выбирает входные файлы/папку результатов;
- интерфейс Avalonia запускает расчёт, отменяет его и рисует предоставленные данные.

Код этих частей, 3D-геометрия, вышки и несколько объектов КИИ в текущее ядро не добавлены.
