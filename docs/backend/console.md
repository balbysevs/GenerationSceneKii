# Консольное приложение RadarPlacement

`RadarPlacement.Console` — отдельное приложение с русским меню. Оно использует
готовые `RadarPlacement.Core` и `RadarPlacement.Serialization`. Расчёты геометрии,
оптимизация и правила JSON не дублируются в консоли. Интерфейс Avalonia не требуется.

## Запуск на Windows

Самый простой вариант — открыть `Start-Console.cmd` в корне репозитория двойным щелчком.
Скрипт переходит в папку проекта, собирает консоль и запускает меню. Нужен установленный
.NET 10 SDK. Отдельные NuGet-пакеты для консоли не добавлены.

Из PowerShell в папке проекта:

```powershell
.\Start-Console.cmd
```

Также можно собрать решение и запустить программу напрямую:

```powershell
dotnet build RadarPlacement.Core.slnx --configuration Release --disable-build-servers -m:1
dotnet run --project src/RadarPlacement.Console --configuration Release --no-build
```

В Visual Studio откройте `RadarPlacement.Core.slnx` и выберите **RadarPlacement.Console**
запускаемым проектом. Рабочая папка доступна в справке (пункт 9): относительно неё считаются
введённые относительные пути и стандартная папка `Result`.

Запуск `Start-Console.cmd` всегда использует корень репозитория как рабочую папку.
Сам скрипт хранится с окончаниями строк CRLF; правило закреплено в `.gitattributes`,
поскольку `cmd.exe` некорректно обрабатывал исходную версию с LF.

## Первое знакомство за минуту

1. Запустите приложение.
2. Введите **8** — загрузится пример сцены и его настройки. Нажмите **Enter** для возврата в меню.
3. Введите **4**, затем нажмите **Enter**, чтобы рассчитать все загруженные сцены.
4. После завершения приложение покажет площадь покрытия и путь к созданному JSON. Нажмите **Enter**.
5. Введите **5**, затем **1**, чтобы увидеть координаты радаров первой сцены; **Enter** вернёт меню.
6. Введите **0** для выхода.

Пример использует два радара радиусом 3000 м, шаг позиций 500 м и шаг покрытия 1000 м.
Это намеренно грубая сетка для быстрого знакомства. Она не задаёт рекомендуемую
точность для всех остальных сцен.

Сцена примера находится в `examples/scene-2d.json`, настройки — в
`examples/solver-settings-2d.json`. При сборке они копируются в папку `Demo` рядом
с исполняемым файлом. Сцена совпадает с контрольным JSON настоящего экспортёра первой
команды; происхождение описано в `tests/RadarPlacement.Serialization.Checks/Fixtures/README.md`.

## Главное меню

| Пункт | Действие |
| --- | --- |
| 1 | Добавить один JSON-файл сцены |
| 2 | Добавить все JSON-сцены непосредственно из указанной папки |
| 3 | Изменить настройки, загрузить их из JSON или сохранить |
| 4 | Рассчитать одну сцену либо все и автоматически сохранить результат каждой |
| 5 | Просмотреть сведения о сценах, показатели покрытия и координаты радаров |

| 7 | Убрать сцены из памяти текущего сеанса |
| 8 | Добавить готовый пример и применить его настройки |
| 9 | Показать справку |
| 0 | Завершить работу |

## Сменяемые экраны и постоянная сводка

В обычном окне консоли выбранное действие заменяет предыдущий экран. В верхней части
главного меню, подменю, расчёта и просмотра результатов сохраняется сводка:

- количество сцен, число результатов с текущими настройками и несохранённых результатов;
- номер и ID текущей сцены;
- количество радаров, общий радиус и оба шага дискретизации;
- процент покрытия последнего результата, его актуальность и состояние сохранения;
- размеры участка, количество помех, папка вывода и включение карт покрытия в JSON.

Текущей становится последняя загруженная или выбранная сцена. При расчёте серии
сводка переключается на обрабатываемую сцену, а при просмотре нескольких результатов —
на просматриваемую. После удаления текущей сцены выбирается первая оставшаяся.
После изменения параметров старый результат получает пометку **ДРУГИЕ НАСТРОЙКИ**;
его собственные параметры можно увидеть в пункте 5.

Стадия расчёта обновляется на месте. Ошибки и итоги остаются на экране до **Enter**.
Если текст не помещается, **PgUp/PgDn** листают страницы под неподвижной сводкой;
это работает и для справки, и для списка сцен, и для координат радаров. При выборе
нескольких сцен пункт 5 показывает отдельный экран каждой сцены, переход — **Enter**.

Рекомендуемый размер окна — от 80 столбцов и 25 строк. При изменении размера страницы
перестраиваются; в ожидании ввода это происходит автоматически. Длинные строки сводки
сокращаются многоточием, полный путь результата доступен в пункте 5, папка вывода —
в пункте 6. В очень низком окне остаются только первые строки сводки.

Длинный ввод прокручивается по горизонтали и не сдвигает панель вверх. Поддерживаются
стрелки влево/вправо, Home/End, Backspace/Delete; **Esc** очищает строку ввода.
**Ctrl+Z** завершает ввод. Вставка пути средствами терминала также работает.

Если стандартный ввод или вывод перенаправлен, приложение использует обычный
построчный режим без управления курсором и дополнительных пауз. Сценарии через stdin
сохраняют прежнюю последовательность команд; `--help` всегда выдаёт обычный текст.

При выборе сцены можно ввести её номер, **Enter**, `все` или `*` для всех, **0** для отмены.
При вводе пути Enter возвращает назад, если в приглашении не указан путь по умолчанию.
Если путь по умолчанию указан, Enter выбирает его, а 0 возвращает назад.

Можно вставлять пути из Проводника, в том числе с кавычками, пробелами и кириллицей.
Поддерживается раскрытие переменных окружения вроде `%USERPROFILE%`.
Пути обрабатываются файловым API; введённые строки не выполняются как команды оболочки.

## Загрузка сцен

Поддерживается текущая 2D-модель: JSON версии 1.0, один прямоугольный КИИ,
прямоугольные помехи вдоль осей, без внутренних дворов. Подробные правила находятся
в [описании JSON](json-2d.md).

При загрузке папки:

- учитываются расширения `.json` и `.JSON`;
- подпапки автоматически не обходятся;
- уже добавленный полный путь пропускается;
- неверный JSON, файл настроек, готовый результат или неподдерживаемая сцена дают
  сообщение с именем файла, но не мешают загрузке остальных;
- в конце показывается число добавленных, повторных и ошибочных файлов.

Одинаковые `sceneId` в разных файлах не объединяются: каждая запись соответствует
отдельному загруженному пути. Два файла с одинаковыми именами из разных папок
также остаются разными сценами.

Загружается снимок содержимого файла. Если вы изменили файл другим приложением,
уберите старую запись из списка и загрузите его заново. Программа не перечитывает
входы посередине расчёта.

## Настройки

Пункт 3 открывает отдельное меню:

1. Количество радаров — целое число от 1 до 10.
2. Общий радиус — число от 3000 до 7000 м.
3. Шаг кандидатов на периметре КИИ — положительное конечное число.
4. Шаг сетки оценки покрытия — положительное конечное число.
5. Ограничения: число позиций, число ячеек, байты битовых буферов.
6. Загрузка JSON-настроек.
7. Сохранение JSON-настроек.
8. Восстановление стандартных настроек.
0. Возвращение в главное меню.

При редактировании чисел Enter оставляет прежнее значение. Десятичная запятая
и точка допускаются, например `250,5` и `250.5`. Неверное значение вызывает повторный
запрос. Групповые разделители разрядов вводить не нужно.

Неудачная загрузка JSON не меняет текущие параметры. При сохранении настроек замена
существующего файла требует явного ответа `д` или `да` (`y`/`yes` тоже принимаются).
Пустой ответ означает отказ. Стандартное имя сохранения — `solver-settings.json`.

Изменение настроек не удаляет прошлые результаты. Они помечаются как рассчитанные
с другими настройками, а просмотр показывает именно параметры того расчёта.
Чтобы применить новые параметры, выполните пункт 4 повторно. Алгоритм по-прежнему
ищет глобальный максимум выбранной дискретной модели, без автоматического огрубления сетки.

## Что отображается во время расчёта

- Номер текущей сцены в выбранной серии и имя файла.
- Подготовка сетки наблюдения.
- Сколько позиций обработано при вычислении видимости, и процент этой стадии.
- Число посещённых узлов точного поиска.
- Лучшее найденное число покрытых ячеек — до окончания это нижняя оценка максимума.
- Прошедшее время.
- После успешного завершения — подтверждение дискретного оптимума, площадь,
  процент покрытия, время расчёта и путь к сохранённому файлу.

Процент завершения точного поиска заранее неизвестен. Консоль не вычисляет его
из числа посещённых узлов и не показывает выдуманное оставшееся время.
Повторные отчёты одной стадии обновляются не чаще одного раза в две секунды
по мере поступления отчётов ядра. Это не отдельный таймер: стадия без новых отчётов
может некоторое время не обновлять строку времени.

## Просмотр результата

Пункт 5 показывает:

- идентификатор и полный путь исходной сцены;
- размеры участка и КИИ, количество помех;
- наличие готового результата и информацию о последней неудачной попытке;
- параметры, с которыми получен именно этот результат;
- размер сетки и число кандидатов;
- число покрытых и наблюдаемых ячеек;
- покрытую и наблюдаемую площадь по сетке в м², процент покрытия;
- подтверждение глобального максимума в дискретной модели;
- количество посещённых и отсечённых узлов поиска;
- координаты X/Y каждого радара и общий радиус;
- последний успешный путь сохранения.

Когда наблюдаемых центров ячеек нет, процент не определён; консоль сообщает это
вместо деления на ноль. Площади — оценки по центрам ячеек, а не точное интегрирование
непрерывной геометрии. Графическая карта сцены в этой консольной версии не рисуется.

## Сохранение результатов

По умолчанию каждый запуск расчёта создаёт новую подпапку `Result/run-…/`.
После каждого успешно завершённого расчёта результат сразу сохраняется туда.
Старая серия не перезаписывается. Имена включают номер сцены в списке и безопасную
часть имени исходного файла, поэтому одинаковые имена входов не конфликтуют.

В пункте 6 можно выбрать другую папку и включить карты покрытия в JSON.
При выключенных картах всё равно сохраняются исходная сцена, радары, параметры
и показатели покрытия. Карты включаются только в следующие сохранения.
Пункт 6 → 3 повторно сохраняет готовые результаты в новую папку запуска без оптимизации,
в том числе с изменённой настройкой включения карт.

Если расчёт завершился, но запись не удалась, результат остаётся в памяти.
Выберите доступную папку и повторите сохранение через пункт 6. При попытке обычного
выхода с несохранённым результатом приложение спросит, действительно ли нужно выйти.
После завершения процесса несохранённые данные восстановить нельзя.

Сохранение старого результата не применяет к нему текущие настройки: в файл всегда
попадают реальные параметры его расчёта. Исходные сцены и ранее сохранённые файлы
не удаляются и не перезаписываются. Папка `Result` и стандартный локальный файл
`solver-settings.json` исключены из Git.

## Отмена и ошибки

**Ctrl+C во время операции** запрашивает отмену и возвращает управление в меню.
Уже сохранённые результаты серии остаются на диске. Незавершённый поиск не выдаётся
за оптимальный результат. При отмене пересчёта остаётся доступен прошлый успешно
полученный результат этой сцены, если он был.

Каждая операция получает новый токен отмены, поэтому следующий расчёт можно запустить
сразу. Вне операции Ctrl+C завершает приложение; штатный выход — пункт 0.
При закрытии входного потока программа также завершается, без бесконечного повторения меню.

Ошибка одной сцены не прекращает расчёт остальных. При недоступной папке запуска
расчёт не начинается. Понятные ошибки ввода и файлов возвращают меню без трассировки стека.
Неожиданная ошибка верхнего уровня завершает процесс с сообщением.

Коды завершения: 0 — обычный выход из меню или справки, 1 — непредвиденная ошибка,
2 — неверные аргументы. Ошибки отдельных действий в интерактивном сеансе отражаются
в сообщениях; последующий штатный выход из меню имеет код 0.
Автоматический пакетный режим через аргументы командной строки пока не предусмотрен.
Поддерживаются только `--help`, `-h`, `/?` и интерактивный запуск без аргументов.

## Структура исходников и проверки

| Файл | Ответственность |
| --- | --- |
| `Program.cs` | Кодировка, запуск и обработчик Ctrl+C |
| `ConsoleApplication.cs` | Главное меню, загрузка, выбор и удаление сцен из списка |
| `ConsoleApplication.Settings.cs` | Редактирование настроек и управление сохранением |
| `ConsoleApplication.Calculations.cs` | Запуск ядра, автоматический экспорт и просмотр |
| `ConsoleApplication.Screen.cs` | Постоянная сводка из актуального состояния сеанса |
| `ConsoleUi.cs` | Общие правила ввода, числа, пути и завершение по EOF |
| `ConsoleUi.Screen.cs` | Смена экранов, страницы, строка ввода и обновление прогресса |
| `ConsoleTerminal.cs` | Отрисовка изменившихся строк и чтение клавиш Windows-консоли |
| `ApplicationSession.cs` | Очередь сцен и результаты текущего сеанса |
| `OperationCancellation.cs` | Жизненный цикл отмены отдельной операции |
| `ProgressDisplay.cs` | Отображение прогресса без засорения окна сообщениями |

В коде оставлены русские summary и комментарии к сохранению состояния и отмене.
Отдельный `RadarPlacement.Console.Checks` проверяет 22 сценария с реальными
библиотеками, включая полный диалог в отдельно запущенном процессе.
В проверках отмены сигнал передаётся тому же контроллеру, что используется обработчиком
Ctrl+C; сама клавиатура Windows этими автоматическими сценариями не эмулируется.
Для экранного режима тестовый терминал записывает кадры и выдаёт нажатия клавиш:
проверяются смена меню, обновление сводки, постраничный просмотр, границы окна,
редактирование длинного пути, сообщения об ошибках и отмена с повторным запуском.

```powershell
dotnet build RadarPlacement.Core.slnx --configuration Release --disable-build-servers -m:1
dotnet run --project tests/RadarPlacement.Console.Checks --configuration Release --no-build
```

Проверяются автоматический экспорт, частично ошибочная серия, повторные имена,
отмена и повторный запуск, сохранность старого результата, восстановление после
ошибки записи, настройки и UTF-8. Ещё 20 проверок ядра и 25 проверок JSON запускаются
своими проектами. Проверки записывают временные файлы только в собственные каталоги
под `bin`, затем удаляют созданные ими папки.
